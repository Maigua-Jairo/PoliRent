# AGENTS.md

PoliRent — sistema de préstamo y recomendación de recursos para las asociaciones de estudiantes de la Escuela Politécnica Nacional (UI y mensajes en español; mantener el texto nuevo en español). Los requisitos están en las historias de usuario HU-001…HU-011 del trabajo de titulación del frontend.

## Layout (monorepo)

- `backend/` — API REST Express + Mongoose (ESM). Entrada `src/index.js`, app en `src/server.js`.
- `frontend/` — SPA React + Vite.
- No hay `package.json` en la raíz: ejecuta los comandos npm dentro de cada carpeta.

## Comandos

```sh
# backend/
npm run dev      # nodemon
npm test         # Jest (ESM vía --experimental-vm-modules) + Supertest; no usa base de datos

# frontend/
npm run dev      # Vite
npm test         # Vitest + Testing Library (jsdom)
npm run lint     # oxlint
npm run build    # producción -> dist/
```

Verificación completa: `npm test` en ambos + `npm run lint` y `npm run build` en el frontend.

## Contrato backend ↔ frontend

- Las reglas de validación están duplicadas a propósito y deben coincidir:
  `backend/src/middlewares/validationMiddleware.js` ↔ `frontend/src/utils/validaciones.js`
  (correo `@epn.edu.ec`, cédula ecuatoriana con dígito verificador y única, teléfono `09XXXXXXXX`, contraseña ≥ 8 con mayúscula/minúscula/número).
- Listas cerradas que deben coincidir: `FACULTADES` (`backend/src/models/Usuario.js` ↔ `frontend/src/utils/validaciones.js`) y `CATEGORIAS`/`ESTADOS` de recursos (`backend/src/models/Recurso.js` ↔ `frontend/src/utils/recursos.jsx`). Límites de recurso: nombre 3–80 (único sin distinguir mayúsculas ni tildes), descripción vacía o 10–500, precio > 0 y ≤ 100000 con 2 decimales (opcional), etiquetas ≤ 15 de 2–30 sin repetir, imagen JPG/PNG/WEBP ≤ 2 MB.
- **Multipart con axios**: `api/axiosCliente.js` usa `Content-Type: application/json` por defecto, y con ese encabezado axios convierte un `FormData` a JSON y descarta los archivos. Toda petición con archivo debe pasar `headers: { 'Content-Type': 'multipart/form-data' }` (ver `services/recursoService.js`).
- Errores: el backend responde `{ msg }`. Un `401` en una petición autenticada cierra la sesión en el frontend (interceptor de `api/axiosCliente.js`), así que los errores de datos deben ser `400`, nunca `401`.
- Registro: siempre crea `estudiante` y no devuelve token; el frontend redirige a `/login`. Los administradores se asignan cambiando `rol` en la base de datos (ningún endpoint acepta `rol`). Hay un **único administrador y no tiene facultad**: `facultad` es obligatoria solo para estudiantes, no sale en las respuestas del administrador y `PUT /api/perfil` con `facultad` de un administrador responde 400. Cada campo vacío del registro o del login responde 400 con su nombre (`El campo contrasena es obligatorio`); el correo debe ser exactamente `usuario@epn.edu.ec` (`Usa tu correo institucional @epn.edu.ec`). El login responde 401 `Correo no registrado` o `Contrasena incorrecta` (mensajes distintos por pedido del revisor) y no exige el dominio institucional.
- `GET /api/recursos` y `GET /api/recursos/:id` son públicos; crear/editar/eliminar exige rol `administrador`. Las imágenes llegan como `multipart/form-data` en el campo `imagen` y se suben a Cloudinary (sin variables `CLOUDINARY_*` la subida responde 503).
- **Precio del recurso**: `precio` (dólares, si se envía > 0 y ≤ 100000 con 2 decimales; por defecto 0 = sin precio; en multipart llega como texto) es el precio de reposición y la base de las penalizaciones. `GET /api/recursos` ya lo devuelve.
- **Solicitud de préstamo** (`POST /api/prestamos`): además de `recursoId`, `fechaDevolucion` y `motivoPrestamo` (antes `motivo`), exige `aceptaTerminos: true` y `docenteReferencia: {nombre (3–100), correo, telefono?}`. Opcionales `fechaEntrega` (`AAAA-MM-DD`, por defecto hoy), `horaEntrega` y `horaDevolucion` (`HH:mm`); se guarda `fechaEntregaProgramada`. `fechaDevolucion` acepta `AAAA-MM-DD` (a `horaDevolucion` o a las 18:00 de Ecuador) o fecha con hora (con `horaDevolucion` además: 400). La devolución debe ser estrictamente posterior a la entrega (mismo día permitido) y como máximo 30 días calendario después del día de la entrega; la entrega no puede ser pasada ni a más de `RESERVA_MAX_DIAS_ANTICIPACION` días. El horario 07:00–18:00 se valida sobre las horas **programadas**, no sobre la hora de envío. Sin `fechaEntrega` ni `horaEntrega` fuera de horario se toma la próxima apertura. Con penalizaciones `pendiente` o `en_revision` responde 400 con el monto (y la parte en revisión). Máximo `MAX_SOLICITUDES_ACTIVAS` (5) solicitudes activas por estudiante. El préstamo devuelve `fechaEntregaProgramada`, `terminos`, `docenteReferencia`, `entrega` y `devolucion` (evidencias solo con `url`; `devolucion.responsableNombre` es quien **recibe** el recurso); nunca `codigoQR`.
- **Comprobante de pago** de penalizaciones: estados `pendiente` → `en_revision` (el estudiante subió el comprobante) → `pagada` (el administrador lo aprobó); desde `en_revision` el administrador puede rechazarlo y vuelve a `pendiente` con `motivoRechazoComprobante`. `en_revision` **sigue contando como deuda** (`totalAdeudado` = pendientes + en revisión; bloquea solicitudes). El estudiante sube la foto con `PUT /api/penalizaciones/:id/comprobante` (`multipart/form-data`, campo `comprobante`, JPG/PNG/WEBP ≤ 2 MB, textos opcionales `referencia` 3–50 y `observaciones` ≤ 200). Cada penalización trae `comprobante: {url, subidoEn, referencia, observaciones}` o `null`, `motivoRechazoComprobante` y `fechaRevision` (nunca `publicId`).
- **Políticas** (`backend/src/helpers/politicasHelper.js`, valores por variables de entorno): atraso 5 % del precio por día o fracción, daño/incompleto 20 %, pérdida 100 % (sin sumar atraso), tope 100 % del precio por préstamo; horario 07:00–18:00 `America/Guayaquil` (`VALIDAR_HORARIO=false` lo desactiva). `GET /api/terminos` (público) devuelve tarifas, horario, `maxSolicitudesActivas` y las frases de los términos.

## Frontend

- **Tailwind v4**: sin `tailwind.config.js`; tokens (`epn-*`, `brand-*`, `font-script`) y `@custom-variant dark` en `src/index.css`.
- **Modo oscuro** por clase `.dark` en `<html>`, manejado por `src/hooks/darkMode.js` (zustand + persist, clave `theme`) y `components/ThemeToggle.jsx`. Todo componente nuevo necesita variantes `dark:`.
- **Sesión**: `src/store/authStore.js` (zustand + persist, clave `polirent-auth`) guarda `token` y `usuario` (con `rol`). Cerrar sesión con `hooks/useCerrarSesion.js`.
- **API**: agrega endpoints como funciones en `src/services/*Service.js`, nunca llamadas axios sueltas en las páginas.
- **Rutas** (`src/App.jsx`): `SoloInvitados` envuelve login/registro/recuperación y, con sesión, redirige a `rutaInicio(usuario)` (`store/authStore.js`): `/dashboard` para estudiantes y `/admin` para administradores; el login usa la misma regla. El catálogo completo vive en la sección `#recursos` de la landing (`Home.jsx` con `components/recursos/CatalogoRecursos.jsx`); `/recursos?…` solo redirige a `/?…#recursos`. `PublicLayout` envuelve la ficha `/recursos/:id` para todos, también con sesión: ahí se reserva, nunca dentro del panel. `AppLayout` (panel) envuelve solo rutas protegidas:
  - `RutaProtegida roles={['estudiante']}`: `/dashboard`, `/recomendaciones`, `/solicitudes`, `/solicitudes/:id`, `/penalizaciones` (el backend solo deja a estudiantes usar `/api/prestamos/mis`, `/api/recomendaciones` y `/api/penalizaciones/mis`);
  - `RutaProtegida` (cualquier rol): `/perfil` (configuración de cuenta, pestañas en `?seccion=perfil|seguridad|notificaciones`);
  - `RutaProtegida roles={['administrador']}`: `/admin` (dashboard), `/admin/penalizaciones` y `/admin/recursos…`.
- **Layouts**: la landing y la ficha del recurso comparten el mismo navbar, `components/layout/NavbarSitio.jsx` (secciones de la landing; fuera de `/` sus enlaces van a `/#seccion` y `Home` se desplaza a la sección). `components/layout/PublicLayout.jsx` lo usa para la ficha. `components/layout/AppLayout.jsx` es el panel: barra lateral fija (panel en móvil) con navegación según el rol, sin el catálogo, y barra superior con buscador global (lleva a `/?buscar=…#recursos`), campana, menú del usuario y `ThemeToggle`. Los invitados no tienen panel: reservar y recibir recomendaciones exige sesión de estudiante. El menú del usuario (`components/layout/MenuUsuario.jsx`) ofrece Mi panel, Página principal (`/`, para seguir explorando), Mi cuenta y Cerrar sesión. Iconos de navegación y paneles en `components/layout/iconos.jsx`. Avatar con iniciales en `components/Avatar.jsx` (aún no hay foto de perfil).
- **Préstamos**: `services/prestamoService.js`, carga en `hooks/useMisPrestamos.js`; estados, pestañas y reglas (`puedeCancelar`, `enCurso`) en `utils/prestamos.js`, que debe coincidir con `ESTADOS_PRESTAMO` de `backend/src/models/Prestamo.js`. No hay `GET` de un préstamo: el detalle lo busca en la lista del estudiante. La reserva (HU-008) se hace en `/recursos/:id` con `components/prestamos/FormularioSolicitud.jsx` (sección `#solicitar`); en el panel no se reserva: las tarjetas de recomendación tienen "Ver en recursos", que abre esa ficha pública; las reglas de fecha (≤ 30 días) y motivo (≤ 300) en `utils/prestamos.js` deben coincidir con `validarSolicitudPrestamo` del backend. **Máximo de solicitudes activas**: con `MAX_SOLICITUDES_ACTIVAS` (5) solicitudes `pendiente`/`aprobado`/`entregado` el backend responde 400 (`Alcanzaste el maximo de 5 solicitudes activas; ...`); reglas en `ESTADOS_ACTIVOS` y `mensajeMaximoSolicitudes` de `backend/src/models/Prestamo.js`. El estudiante solo cancela solicitudes `pendiente`. El aviso en la ficha queda a cargo del frontend.
- **QR**: no se implementa en el frontend (decisión del proyecto). El backend todavía genera y escanea QR (`/api/prestamos/:id/qr`, `/api/prestamos/escanear`) ; no lo consumas desde el frontend. Para registrar entrega y devolución sin lector de QR existen `PUT /api/prestamos/:id/entregar` y `PUT /api/prestamos/:id/devolver` (ver "Pendiente en el frontend").
- **Dashboard del administrador** (`pages/admin/DashboardAdmin.jsx`, componentes en `components/admin/`): carga `GET /api/prestamos` y `GET /api/recursos` (`hooks/useDashboardAdmin.js`); cifras, inventario, gráficos y actividad se calculan en el cliente (`utils/estadisticas.js`). Aprueba y rechaza solicitudes (`aprobarPrestamo`, `rechazarPrestamo`). "Generar reporte" descarga un CSV (`;` + BOM) armado en el navegador (`utils/reporte.js`). No hay conteo de usuarios ni tendencias (sin endpoint ni historial). La barra lateral del admin muestra el menú completo del diseño; las pantallas inexistentes salen como "Pronto". Colores de categoría en gráficos: `grafico` en `CATEGORIAS` (paleta validada para claro y oscuro).
- **Recomendaciones**: `services/recomendacionService.js`; reglas del contexto (5–500) en `utils/recomendaciones.js`. El filtro por categoría se aplica en el cliente (el backend no lo acepta y solo recomienda recursos disponibles). Las consultas recientes se guardan por usuario en `store/consultasStore.js` (clave `polirent-consultas`).
- **Datos provisionales**: ubicación, horario y responsable de entrega (`INFO_ENTREGA`), código de recurso (`codigoRecurso`), notificaciones y "Cambiar foto" son texto fijo hasta que el backend los exponga.
- **Catálogo** (sección Recursos de la landing): los filtros viven en la URL (`hooks/useFiltrosRecursos.js`), la carga en `hooks/useRecursos.js`; componentes en `components/recursos/`. Las fotos de recursos se muestran siempre desde `recurso.imagen` con `ImagenRecurso` (respaldo con el icono de la categoría). Animación de entrada `motion-safe:animate-aparecer` definida en `src/index.css`.
- **Formularios**: React Hook Form; adapta los validadores con `regla()` de `utils/validaciones.js`. Primitivas compartidas: `Field`/`AuthLayout`, `PasswordInput`, `Alerta`, `Icon`, `DialogoConfirmacion`, clases (incluida `pestana()`) en `components/auth/authStyles.jsx`.
- oxlint **no detecta identificadores sin definir** y el build tampoco: cada pantalla nueva debe tener al menos una prueba que la renderice.
- `src/pages/Home.jsx` usa `/images/hero-campus.jpg` y `/images/students.jpg`, que aún no existen en `public/images/` (se ve el degradado de respaldo).
- Lint tiene 2 advertencias `react(purity)` conocidas (`new Date()` en `AuthLayout.jsx` y `Home.jsx`); no bloquean.

## Backend

- Archivos vacíos reservados para trabajo futuro: préstamos (`prestamoController`, `prestamoRouter`, `models/Prestamo`), recomendaciones (`recomendacionController`, `recomendacionRouter`), QR (`helpers/qrHelper`), `helpers/responseHelper`, `routers/index`. No los borres.
- **Asistente** `POST /api/asistente` (público, sesión opcional con `verificarTokenOpcional`): un solo chat que responde `tipo` `ayuda` | `recomendacion` | `fuera_de_tema`. Motor híbrido: `helpers/asistenteHelper.js` (preguntas frecuentes con palabras clave + TF-IDF de `recomendacionHelper`) y, con `GEMINI_API_KEY`, `helpers/geminiHelper.js` (fetch nativo, JSON validado; solo puede elegir ids de recursos enviados). Las dudas que el motor local reconoce con seguridad (`seguro`) no llaman a Gemini; si Gemini falla o tarda (`GEMINI_TIMEOUT_MS`, el nivel gratuito tarda 10-20 s) responde el motor local. Al cambiar reglas del sistema, actualiza también `PREGUNTAS_FRECUENTES`.
- Recursos de ejemplo: `npm run seed` (`src/seed/`), inserta solo los nombres que faltan; `-- --dry` para simular.
- `POST /api/recuperar-clave` envía el enlace `FRONTEND_URL/recuperar-clave/:token` al correo institucional por SMTP (`src/config/mailer.js`, variables `SMTP_*`). Sin SMTP: en producción responde 503; con `NODE_ENV=development` además devuelve el token en la respuesta para probar sin correo.
- `GET /api/recursos` acepta `categoria`, `estado` y `buscar` (texto literal en nombre/descripción, sin distinguir mayúsculas).
- **Políticas** en `helpers/politicasHelper.js` (funciones puras que leen `process.env` al llamarse): `PENALIZACION_ATRASO_DIA`, `PENALIZACION_DANIO`, `PENALIZACION_PERDIDA`, `HORARIO_INICIO`, `HORARIO_FIN`, `VALIDAR_HORARIO`, `MAX_SOLICITUDES_ACTIVAS` (5), `MOTIVO_RECHAZO_MIN`/`MAX` (30/200), `ENTREGA_TOLERANCIA_MIN` (30), `RESERVA_MAX_DIAS_ANTICIPACION` (30), `RECORDATORIO_HORAS_ANTES` (24,1) y `RECORDATORIO_INTERVALO_MIN` (15); utilidades de fecha en Ecuador (`combinarFechaHora`, `formatearFechaHora` dd/MM/yyyy HH:mm). Los tests ponen `VALIDAR_HORARIO=false` salvo los de horario. Al cambiar tarifas u horario, las respuestas del asistente (`PREGUNTAS_FRECUENTES` con getters) y `textoTerminos()` se actualizan solas.
- **Entrega y devolución**: `POST /api/prestamos/escanear` (QR), `PUT /api/prestamos/:id/entregar` y `PUT /api/prestamos/:id/devolver` comparten `registrarMovimiento` (`prestamoController.js`). Aceptan JSON o `multipart/form-data` con `responsable` (por defecto el administrador), `observaciones` y la foto `evidencia` (`subirEvidenciaPrestamo`, carpeta `polirent/evidencias`). La devolución recibe `condicion` (`bueno`|`danado`|`incompleto`|`perdido`); `danado`/`incompleto` exigen evidencia; el recurso queda `disponible` solo si es `bueno` (si no, `mantenimiento`). Fuera de horario responde 400, salvo `perdido`. La entrega solo es desde `aprobado` y no antes de `fechaEntregaProgramada` menos `ENTREGA_TOLERANCIA_MIN` (las solicitudes antiguas sin ese campo no se validan). En la devolución `responsable` (cuerpo) y `devolucion.recibidoPor` (respuesta) son quien **recibe** el recurso; en la base de datos se guarda como `responsableNombre`. Crea un documento `Penalizacion` por cada penalización y notifica (`penalizacion`); responde además `penalizaciones`, `totalPenalizado` y `advertencias` (recurso sin precio). `GET /api/prestamos/:id` (dueño o administrador) sirve para consultar el préstamo durante la entrega.
- **Penalizaciones** (`models/Penalizacion.js`, `penalizacionController.js`, `penalizacionRouter.js`; lógica compartida en `helpers/penalizacionHelper.js`): `GET /api/penalizaciones/mis` (estudiante: `totalAdeudado`, `atrasoEnCurso` calculado al vuelo), `GET /api/penalizaciones` (administrador, filtros `estado`, `usuario`, `desde`, `hasta`), `PUT /api/penalizaciones/:id/pagar` y `PUT /api/penalizaciones/:id/anular` (`{motivo}` 3–200; ambas desde `pendiente` o `en_revision`: pagar desde `pendiente` es un pago en efectivo sin comprobante). El docente de referencia solo lo ve el administrador (no se le envía correo).
  - Comprobante: `PUT /api/penalizaciones/:id/comprobante` (estudiante; orden de middlewares: sesión y rol → `subirComprobante` (multer) → validadores; una penalización ajena o inexistente responde el mismo 404; en `en_revision` el nuevo reemplaza al anterior y borra la imagen vieja de Cloudinary, carpeta `polirent/comprobantes`; notifica a todos los administradores) y `PUT /api/penalizaciones/:id/rechazar-comprobante` (administrador, `{motivo}` 3–200, solo desde `en_revision`; borra la imagen y notifica al estudiante). `pagar` guarda `revisadaPor`/`fechaRevision` y conserva el comprobante. `GET /api/penalizaciones?estado=en_revision` es la cola de revisión; la lista devuelve `totalPendiente` y `totalEnRevision`; `/mis` devuelve además `totalEnRevision`. Métricas: `penalizaciones.enRevision {cantidad, monto}`; el reporte de penalizaciones suma las columnas `Comprobante (URL)`, `Referencia` y `Revisada el` (y `Pagada el`, antes `Fecha de pago`). Cada penalización trae `fechaRegistro` (`createdAt`) y `fechaPago` (null si no está pagada).
  - Concurrencia: `Prestamo` y `Penalizacion` usan `optimisticConcurrency` (Mongoose); si dos peticiones cambian el mismo documento a la vez, `save()` lanza `VersionError` y el controlador responde 400 (`MSG_CONFLICTO` de `helpers/responseHelper.js`).
- **Solicitudes**: rechazar exige `motivoRechazo` de 30 a 200 caracteres; cancelar solo desde `pendiente` y su respuesta trae `recurso.nombre` sin `fechaDevolucion`/`fechaDevolucionReal`/`devolucion`. Dos solicitudes simultáneas no superan el máximo: tras crear se vuelve a contar y la sobrante se borra (400).
- **Recursos**: `DELETE /api/recursos/:id` solo con estado `disponible` y sin solicitudes activas. El nombre único se busca con `collation({locale: 'es', strength: 1})` (sin índice único nuevo) y al actualizar excluye al propio recurso. Los campos del sistema (`_id`, `imagenId`, `createdAt`, `updatedAt`, `__v`) responden 400.
- **Recordatorios** (`helpers/recordatorioHelper.js`): `enviarRecordatorios(ahora)` avisa (`recordatorio`, `Recuerda devolver <recurso> el dd/MM/yyyy a las HH:mm`) los préstamos `entregado` que vencen dentro de `RECORDATORIO_HORAS_ANTES`; sin duplicados con `recordatoriosEnviados` y `updateOne` condicional antes de notificar. `index.js` lo arranca con `setInterval(...).unref()` (no en `NODE_ENV=test`) y `server.js` hace un disparo oportunista por petición como máximo una vez por intervalo (Render duerme el plan gratuito). Convive con los avisos que `GET /api/notificaciones` ya generaba (≤ 2 días y vencido).
- **Métricas**: `GET /api/metricas` agrega `penalizaciones` (con `recaudado {total, porRecurso, porTipo}`: solo pagadas, de mayor a menor, porcentajes que suman 100) y `recursosParaReponer` (`helpers/metricasHelper.js`: alta demanda ≥ 60 % de ocupación en 30 días, daños, pérdidas, mantenimiento). Reportes: columnas nuevas en `/api/reportes/prestamos` y `/api/reportes/recursos`, y `GET /api/reportes/penalizaciones` (CSV con `celdaCSV` y BOM).
- **Asistente**: preguntas frecuentes `horario`, `penalizaciones`, `pagar_penalizacion` (flujo del comprobante), `perdida_dano`, `docente_referencia`, `historial_notificaciones`, `evidencia`, `maximo_solicitudes` (antes `prestamo_unico`), `pedir_hoy` y `recordatorios`; `responderSolicitudesActivas` contesta "¿cuántas solicitudes puedo hacer?" con la cuenta real del estudiante (`Tienes X de 5 solicitudes activas; puedes pedir N recurso(s) mas`) antes del motor local y de Gemini; la nota de recomendaciones solo aparece al llegar al máximo; las respuestas con montos, horario o plazo son getters que leen `tarifas()`, `horario()` y `DIAS_MAX_PRESTAMO` (`politicasHelper.js`). `responderDeuda` responde "¿cuánto debo?" con los datos reales del estudiante antes del motor local y de Gemini (separa lo pendiente de lo que está en revisión; a Gemini se le pasa la deuda en `contextoUsuario`). Gemini recibe además `REGLAS DEL SISTEMA` (`reglasNegocio()` de `geminiHelper.js`: máximo de solicitudes activas, entrega y devolución por hora dentro del horario, 30 días, cancelar solo pendiente, recordatorios, tarifas y flujo del comprobante; en `contextoUsuario` va cuántas solicitudes activas tiene) y la orden de no inventar precios; la lista de recursos que se le envía no incluye precios.
- **Recomendador** (`helpers/recomendacionHelper.js`): además de `GRUPOS_RELACIONADOS`, `VARIANTES_TEXTO` une formas derivadas y sinónimos con el término del catálogo (palabra completa, sin reglas de derivación: `red` no coincide con `redaccion`). El parecido directo y el de términos relacionados se calculan por separado (`PESO_COMPLEMENTO`) para que el vocabulario relacionado no supere a las coincidencias directas. Banco de calidad: `tests/casosCalidad.js` (catálogo de la semilla + recursos de `preciosRecursos.js` con etiquetas aproximadas) y `tests/recomendacionCalidad.test.js`; al cambiar el vocabulario, todas sus consultas deben seguir pasando.
- **Validación y errores**: los recursos validan `etiquetas` (arreglo o texto con comas, ≤ 15 de 2–30 caracteres, sin repetir; cada error nombra el campo) e `imagen` en texto (vacía o URL http(s) ≤ 500) y nunca devuelven `imagenId`. Cuerpo JSON > 100 KB, JSON/multipart mal formados o charset no soportado responden 400; multer acepta un solo archivo y ≤ 20 campos de texto. Si la base de datos falla al verificar el token, `verificarTokenJWT` responde 500 (no 401, que cerraría la sesión en el frontend). `x-powered-by` está desactivado.
- **Swagger**: `tests/openapi.test.js` falla si una ruta de `src/routers/` no está en `src/docs/openapi.js` o viceversa: documenta cada ruta nueva.
